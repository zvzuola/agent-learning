# 生产级 Agent 学习计划

## 1. 最终目标

完成课程后，项目应交付一个可部署的业务 Agent，并满足：

- **行为正确**：任务决策、工具选择和结束状态都有自动化证据。
- **工具可靠**：Schema、业务校验、超时、幂等、权限和副作用策略齐全。
- **状态可恢复**：线程隔离、Checkpoint、版本迁移、中断恢复和取消可验证。
- **上下文受控**：历史裁剪、摘要、记忆和 Token/成本预算明确。
- **行为可评测**：具备任务集、轨迹断言、工具指标和质量回归门禁。
- **安全可治理**：最小权限、人工审批、敏感信息保护和注入防御完整。
- **生产可运维**：日志、Trace、SLO、并发控制、发布和故障演练齐备。

## 2. 技术分层

| 层 | 方案 | 教程职责 |
|---|---|---|
| 模型 SDK | `@anthropic-ai/sdk` | 作为依赖使用，不学习通信协议 |
| Agent Runtime | 本项目 `CodingAgent` | 控制循环、预算、状态、事件和恢复 |
| 业务工具 | JSON Schema + Zod + 注入依赖 | 实现并验证业务能力 |
| 状态存储 | Checkpoint/Store 适配器 | 从内存逐步替换为数据库 |
| 治理与运维 | Policy、Eval、Trace、SLO | 建立生产闭环 |

## 3. 12 周执行计划

| 周 | 主题 | 核心问题 | 代码交付物 | 验收证据 |
|---|---|---|---|---|
| 1 | Agent 核心循环 | Agent 如何决策、行动、观察和停止？ | 循环、工具注册、预算与事件 | 文本与工具轨迹测试 |
| 2 | 生产级工具工程 | 如何让工具调用安全、可靠、可重复？ | Tool Policy、超时、幂等与错误分类 | 故障注入和重复调用测试 |
| 3 | 状态与 Checkpoint | 如何隔离线程并从中断处恢复？ | 持久 Checkpoint、状态版本、租户隔离 | 重启恢复与跨租户测试 |
| 4 | 上下文与预算 | 如何控制历史、Token、成本和墙钟时间？ | Context Manager、裁剪、摘要与预算 | 长会话压力实验 |
| 5 | 任务规划与工作流 | 复杂任务如何拆分、路由和动态修正？ | Planner、状态机、并行与子流程 | 多分支任务完成率 |
| 6 | 人工审批 | 高风险动作如何暂停、审批和补偿？ | Approval Gate、Resume、补偿动作 | 批准/拒绝/恢复测试 |
| 7 | 记忆与 RAG | 什么该记、何时检索、如何引用？ | 记忆策略、检索与引用工具 | Recall 和引用正确性评测 |
| 8 | MCP | 如何接入并治理标准化外部工具？ | MCP Adapter、能力发现与权限过滤 | 不可信工具测试 |
| 9 | 多 Agent | 何时拆分角色，如何避免协作失控？ | Supervisor、Handoff、子 Agent | 与单 Agent 的质量/成本对照 |
| 10 | Agent 评测 | 如何证明一次改动真的更好？ | 数据集、轨迹评测、回归报告 | CI 质量门禁 |
| 11 | 安全与可观测性 | 如何防越权并快速定位坏轨迹？ | Policy、审计事件、Trace 与指标 | 红队用例和 SLO 验证 |
| 12 | 生产部署 | 如何承载真实流量并恢复故障？ | API、队列、并发控制、Runbook | 压测、灰度和故障演练 |

建议每周投入 8-12 小时：概念与设计 20%，实现 35%，实验与测试 35%，复盘 10%。

## 4. 三阶段里程碑

### M1：可控单 Agent（第 1-4 周）

Agent 能可靠执行工具、管理线程和上下文，并在预算耗尽、模型失败或工具失败时返回明确状态。

### M2：复杂有状态任务（第 5-9 周）

具备规划、审批、记忆、RAG、MCP 和多 Agent 协作能力，并能解释何时不应增加这些复杂度。

### M3：生产闭环（第 10-12 周）

用评测驱动迭代，建立安全与权限边界、Agent SLO、发布门禁和故障恢复手册。

## 5. 每课固定产物

1. `docs/NN-topic.md`：Agent 设计、适用边界、失败模式和生产检查表。
2. `src/`：可复用实现，不把关键逻辑藏在临时脚本中。
3. `examples/lesson-NN-*.js`：调用真实模型的可运行示例，用于观察实际决策、工具调用和事件轨迹。
4. `test/`：使用 Fake Client 确定性验证成功、边界、错误、恢复和安全场景。
